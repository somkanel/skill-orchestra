# 发布与草案交付

## 当前本地草案

运行检查后，用 `python3 tools/package.py --output <空目录>` 生成 `-draft.zip` 与 SHA-256 文件。工具只收集指定源码路径，拒绝符号链接和未知文件类型，跳过 Python 缓存，并使用固定 ZIP 元信息。草案包可复验字节一致，但工作区文件仍须人工检查，不能保证其中没有被误写入源码的私人文本。

草案包不是从 Git 标签构建的公开 Release。它不建立版本标签、不上传、不更改安装目录。解压后必须检查三个技能完整性，并运行评分示例。

## 将来公开发布

1. 用户确定目标仓库、公开范围并授权发布，创建或关联仓库；不猜测地址。
2. 同步 VERSION、更新记录、技能版本、中英文说明和真实验证状态。
3. 执行项目检查、完整回归和技能结构校验；按评测文档取得真实 Harness 行为证据。
4. 检查差异与发布文件，不包含设计归档、私有任务、技能库存、日志、凭据或账户配置。
5. 提交并推送获准内容，等待远端 CI，通过后在已验证提交创建匹配 VERSION 的标签；不移动已发布标签。
6. 从该标签用 `git archive` 创建正式 ZIP，并生成 SHA-256。正式发布不得把工作区草案包直接冒充标签产物。
7. 发布中英文说明与附件，下载后核对标签、校验值及 ZIP 与标签文件一致性。

MIT 许可文件存在于项目及三个技能目录中。评分与检查工具仅使用标准库，没有分发第三方代码、模型或二进制。
