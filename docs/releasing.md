# 发布与草案交付

## 本地草案

运行检查后，用 `python3 tools/package.py --output <空目录>` 生成 `-draft.zip` 与 SHA-256。工具只收集指定源码路径，拒绝源码符号链接、已有输出路径（包括悬空链接）和未知文件类型，跳过 Python 缓存，并使用固定 ZIP 元信息。输出以独占方式创建；异常中断可能留下不完整产物，应检查后改用新空目录，不自动清理已有文件。

草案包可复验字节一致，但不能保证源码没有被误写入私人文本。它不建立标签、不上传、不更改安装目录，也不替代标签构建的公开附件。

## 公开预览发布

1. 在用户授权的仓库与公开范围内工作，检查身份、远端、分支及工作区，不推送无关内容。
2. 同步 VERSION、技能版本、中英文说明、更新记录与真实验证状态。
3. 执行 `python3 tools/check.py`、`python3 -m unittest discover -s tests -v` 和评分示例；技能结构与真实宿主验证的范围单独记录，不能把程序测试当行为证明。
4. 检查公开文件不包含私有任务、技能库存、日志、凭据、账户配置或缓存。
5. 提交并推送，等待远端 CI 通过，在该提交创建匹配 VERSION 的标签；不移动已发布标签。
6. 运行 `git archive --format=zip --prefix=skill-orchestra-<版本>/ -o <输出ZIP> v<版本>`，计算 SHA-256；正式附件只能从相应标签构建。
7. 发布中英文说明与 ZIP、SHA-256 附件，标为预览版；下载回读，核对校验值及归档中每个文件与标签内容一致。
8. 检查默认分支远端 SHA、CI、标签、Release 附件及本地状态，完成交付。

首批历史版本按[快照说明](history.md)补录：保留原样、标为历史开发预览，0.2.0 明确撤回；没有独立快照的 0.2.1 不伪造标签。推荐安装入口只指向当前公开预览版。
